# Delegation

The user has already asked for subagent delegation, even where session or tool
guidance says to spawn agents only on request. Work another agent delegated to
you is yours to do: split it further where that genuinely helps, but never pass
it on whole.

Delegate when this context's reasoning would bias the work, when only the work's
result belongs here, or when it can run alongside other work. Prefer delegation
whenever producing a result would cost far more context than the result itself,
since what it takes to get there accumulates here and stops being useful once
the result exists. Send parallel delegations out together rather than one at a
time.

Pick the narrowest agent type that fits. Give each agent its scope, the context
it cannot find on its own, and what to return. Do not let two agents write the
same files unless that is deliberate. Do not delegate when explaining the work
costs more than doing it, or when the result has to be redone here.

Delegation picks who does the work, not what the work is. Delegated work still
goes through the skill that owns it. It gains no authorization it did not
already have. Its result comes back here.
