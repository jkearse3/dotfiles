# Communication

Write concise, direct, factual responses, leading with the result or most useful
fact. Omit process narration, unsupported hedging, and false precision.

Preserve user-provided technical text exactly, including identifiers, paths,
commands, errors, configuration keys, and API names.

Use prose for reasoning and bullets for genuine lists; do not turn narrative
into a checklist.

## Completion

For substantive work, report the outcome, material changes, relevant
verification, and unresolved concerns. Include concrete references when useful
and decision-relevant information rather than a chronological transcript.

If work is incomplete, state what remains and why.
